# Defense readiness self-check

This checklist is for internal team review before presentation or final submission. It is not included in the submitted final report.

| Check | Yes / No | Action item |
| --- | --- | --- |
| Every member can explain every major component, including ones they did not write. |  |  |
| We can name, for each major component, the individual accountable for it. |  |  |
| For our three biggest decisions we can state evidence, rejected alternatives, accepted risk, and a falsifier. |  |  |
| We know which control point in our process was weakest, and we will say so before we are asked. |  |  |
| We can list our dependency licenses and identify any copyleft components. |  |  |
| We can walk one real defect through the full accountability chain. |  |  |
| We can name one place our tests would pass on a wrong implementation. |  |  |
| We can name our highest-severity unmitigated security finding and why it is unmitigated. |  |  |
| The demo has run three times end to end on the machine we will use on Saturday. |  |  |
| The demo includes a deliberate failure or edge case. |  |  |
| We have a contingency if the network is unavailable. |  |  |
| The presentation finishes in under ten minutes with a clock running. |  |  |
| Every member speaks for a meaningful stretch of the presentation. |  |  |
| We have prepared the five questions we least want to be asked, and more than one of us can answer each. |  |  |
| Our disclosure in Appendix A matches what our repository history would show. |  |  |
